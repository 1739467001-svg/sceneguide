## 🔴 「授权成功却不生效」的根因（2026-11-24 查清，踩了两次）

官方 runner 报 `global_blocker: AUTHORIZATION_INVALID`、`signing/application` 全部
`QUERY_FAILED`，但 `alipay-cli whoami` 显示已登录、scope 也对。根因是**两层**：

**第一层 · scope 不够**：官方策略表里「AI 按量付费」要求
`app:all,machine_pay:write,agmnt:write`。只有 `app:write`（写权限）不够，
`app`（全部应用权限）才是 `app:all`。网关在权限层直接拦。

**第二层（关键）· CLI 的通用 device-flow 授权给不了 ctx**：
官方脚本调 `ar-query.queryArInfosBySalesProd` 时固定带 `"ctx":{}`，
而 ctx **只能由产品级授权生成**，链接必须是
`https://aipay.alipay.com/cli-auth?deviceCode=…&productCode=…&mccCode=…`。
官方策略表原文：「授权链接只由 auth.sh 构造并校验固定域名、路径和参数；
**禁用 verification_url**」——
即 CLI 那个 `open.alipay.com/ai/ai-resource-center/cli-auth?device_code=…`
只给 scope，**不建立产品/MCC 绑定**，所以 ctx 永远是空的。

**触发方式**：`auth init` 在「已登录但产品上下文无效」时走 `AUTH_FLOW:SKIP`
分支，**不会**重新发起授权。必须先 `alipay-cli logout`，让它重新走
`alipay-cli login --scope` 才会用正确 scope 生成产品级 deviceCode 与那个链接。

⚠️ 三次踩坑记录：
1. 用 CLI 的 `verification_url` 授权 → 授权成功但 ctx 仍空 → 一直 QUERY_FAILED
2. `auth init` 报「产品名称、salesCode 和 scope 不属于同一固定产品映射」
   → 产品名必须**逐字**是「AI 按量付费」（中间有空格）
3. `auth init` 报「MCC 校验失败」→ 那不是 MCC 选错了，是 ctx 空导致 ar-query 报错
