## 链路长什么样

1. 商家本地构造 Payment-Needed（字典序拼 key=value&，RSA2 签名）
   → HTTP 402 + Payment-Needed 头
2. 买方 Agent 把报文原样交给支付宝技能，引导用户完成支付
3. 买方携 Payment-Proof 重试同一请求
4. 商家五项业务核验：active / amount / out_trade_no / resource_id / trade_no 未重复履约
5. 幂等履约 → fulfillment.confirm 履约回执 → HTTP 200 + Payment-Validation 头

## 三个实测踩坑（官方文档里没写清楚的那部分）

① **Payment-Needed 是嵌套的**（{protocol, method}），但**签名只覆盖扁平的 8 个字段**
   ——两层结构不一致，签名时按扁平子集拼。
② 签名串按 key 字典序拼 `key=value&`，且 `seller_signature` 不参与自身签名。
③ alipay-sdk 只吃 PKCS#1（`-----BEGIN RSA PRIVATE KEY-----`），
   PKCS#8 会报 `DECODER routines::unsupported`。

## 三个我自己的工程决定

① **官方按量付费不提供自动 token 计量**，所以我自己建了四维计量层
   （调用次数 / token / 路径长度 / 点位数）——只记录、不参与扣费，
   因为平台要求注册价必须等于实收金额。
② **多额度商品必须有真实权益台账**。买了「十次导览包」却只给一次，
   那不叫商业化，叫装饰。所以我做了次数余额：付清后额度到账，
   后续调用直接扣减，耗尽才回到 402。
③ **自测订单永远单独标注**。沙箱里自己付钱不算付费用户，
   看板把 demo 与 api 来源拆开——反刷量得是设计出来的，不是嘴上说说。

## 为什么路线是真的

场景数据直接来自 OpenStreetMap 原始数据（134 个命名地标 / 597 条路网边 /
113 栋建筑多边形轮廓），路线在场景图上跑最短路，输出几何哈希供复算。
大模型编不出「沿哪条步道走、经过哪些路口」，但真实数据可以。

## 5. 分发节奏（别一天发完）

> ⚠️ **前置条件：作品必须先提交并审核通过。**
> 官方影响力统计的是「参赛作品详情页」上的浏览/点赞/评论——作品没提交就没有详情页，
> 没有详情页，帖子引不过去，分发等于空转。
> 所以顺序是：**提交作品 → 审核通过 → 拿到官方作品详情页 URL → 再铺分发**。

| 时点 | 动作 | 目的 |
|---|---|---|
| 提交当天 | 拿到官方作品详情页 URL，填进本包 §0 的槽位 | 没有它，下面所有引流都白做 |
| 审核通过当天 | GitHub / OSCHINA 首页自荐 + 置顶仓库 | 让评委能看见代码 |
| 审核通过当天 | 博客园 / CSDN 发长贴（§1） | 拿技术圈的第一批评论 |
| D+2 | 掘金 / 公众号发长贴（换标题） | 换一批人看 |
| D+3 | 一句话短贴（§3）+ 7 个渠道二维码 | 拉第一次访问 |
| D+4–D+7 | 研学社群 / 家长群 / 同事转发（§4） | **拉第一批真实付费用户** |
| D+7 起 | 每周在官方作品页回复每一条评论 | 评论回复本身也是互动量 |
| 一直铺到 **12.09** | 每周至少 2 条新帖 + 每日回评论 | 影响力是**累计互动量**，不是一次性峰值 |

> 🔴 **两处最容易白忙的**：
> ① 只发自己站的链接、不引官方作品页 → 浏览量在我们站上，**官方那 20% 一分不加**；
> ② 12.09 之前就发完不发了 → 影响力按**累计**算，且初选在 12.10–12.14，
>    最后两周的互动和最后一周的互动一样值钱。**要一直铺到截止。**
