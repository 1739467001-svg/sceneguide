### 多额度商品（`pack10`）的服务端行为（注册时请知悉）

`pack10` 是一次付费、**十次交付**，不是一次付费一次交付：

1. 买家支付 ¥4.50 → 订单履约 → 服务端在**权益台账**里发放 10 次额度
   （`entitlements` 表，`out_trade_no` 唯一 → 同一笔订单不会重复发放）；
2. 本次交付即扣 1 次 → 余额 9 次；
3. 之后同一访客再调用 `GET /api/v1/guide`（**不带** Payment-Proof）
   → 服务端直接从余额扣 1 次并交付，**不再产生新的扣费**；
4. 余额耗尽 → 重新回到 402 支付挑战。

因此**注册价必须仍然是 ¥4.50 整**（收银侧一次扣 4.50），
不能注册成 ¥0.45/次——平台按「服务单价 × 1」收钱，额度属于服务端交付侧的权益。

> 验收脚本会实测这条链路：`bash scripts/verify.sh` 的第 11 项。

## 请求示例（注册表单「请求示例」栏可直接粘贴）

```bash
# ① 首次调用（无支付凭证）→ HTTP 402 + Payment-Needed 响应头（Base64URL 账单）
curl -s -D - "https://121.43.80.231/sceneguide/api/v1/guide?scene=zjgsu-xiasha&query=从A教学楼到C教学楼怎么走"

# 响应：
# HTTP/1.1 402 Payment Required
# Payment-Needed: eyJwcm90b2NvbCI6eyJvdXRfdHJhZGVfbm8iOiJTR18...
# 响应体：{"code":"Payment-Needed","message":"需要支付","out_trade_no":"SG_...","amount":"0.50","currency":"CNY","goods_name":"单次导览 · 三维场景导览"}
#
# 将 Payment-Needed 头交给支付宝 alipay-pay-for-402-service 技能引导用户付款。

# ② 携带支付凭证重试（Payment-Proof 为付款后所得，Base64URL JSON）→ HTTP 200 + 资源
curl -s -H "Payment-Proof: <Base64URL>" \
  "https://121.43.80.231/sceneguide/api/v1/guide?scene=zjgsu-xiasha&query=从A教学楼到C教学楼怎么走"
```

## 提交后

1. 控制台状态会经历「审核中 → 审核通过」；通过后拿到**每个服务的真实 `service_id`**
2. 把三个 `service_id` 写入服务器上的 `config/production.json` 对应档位（**不要**提交进 git）
3. 重启服务：`sudo systemctl restart sceneguide`
4. 跑一次生产验证：`BASE_URL=https://<域名> bash scripts/verify.sh`
