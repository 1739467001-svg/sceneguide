## 推荐路径：60.205.204.162 + 独立端口 3100

### 1. 阿里云控制台放行端口（你来，约 2 分钟）

ECS 控制台 → 实例 `60.205.204.162` → 安全组 → 配置规则 → **入方向添加**：

| 协议 | 端口 | 授权对象 | 描述 |
|---|---|---|---|
| TCP | 3100 | 0.0.0.0/0 | sceneguide-demo |

同时检查 **22 端口**是否对本机 IP 放行——被拦了就顺手加一条（授权对象填你的出口 IP 更安全）。

### 2. 服务器侧初始化（一次性，SSH 进去后）

```bash
# Node ≥ 20（Ubuntu/Debian）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt-get install -y nodejs
# 或 CentOS/Alibaba Cloud Linux: curl -fsSL https://rpm.nodesource.com/setup_20.x | bash -

useradd -m -s /bin/bash sguser || true
mkdir -p /opt/sceneguide && chown sguser /opt/sceneguide
cp /tmp/sg-deploy/sceneguide.service /etc/systemd/system/
# 编辑单元：Environment=PORT=3100；ALIPAY_ENV=production 先注释（生产密钥未就绪前以沙箱上线）
vim /etc/systemd/system/sceneguide.service
systemctl daemon-reload
```

### 3. 发布（每次更新后）

```bash
SERVER=root@60.205.204.162 bash deploy/deploy.sh
# deploy.sh 支持参数：
#   PORT=3100            远端服务端口（默认 3000）
#   HEALTH_PATH=/healthz 健康检查路径
```

### 4. 沙箱密钥（让线上先跑通演示）

```bash
scp scene-guide/.alipay-sandbox.json root@60.205.204.162:/opt/sceneguide/scene-guide/
ssh root@60.205.204.162 \
  "chown sguser /opt/sceneguide/scene-guide/.alipay-sandbox.json && chmod 600 $_"
```

### 5. 验证（本机直接打外网地址）

```bash
curl -i "http://60.205.204.162:3100/api/v1/guide?scene=zjgsu-xiasha&query=test"
#   期望：HTTP 402 + Payment-Needed 头
BASE_URL=http://60.205.204.162:3100 bash scripts/verify.sh
#   期望：39 项全绿
```

### 6. 提交 service_id 注册

用 **`提交材料/服务注册信息包.md`** 逐字段提交，
可访问地址填 `http://60.205.204.162:3100/api/v1/guide`。

### 7. 域名备案通过后（升级）

1. Nginx 加 server 块（`deploy/nginx.conf` 模板）：域名 → proxy 127.0.0.1:3100
2. certbot 签 HTTPS
3. `config/production.json` 写入生产密钥 + 真实 service_id → 单元文件启用 `ALIPAY_ENV=production` → 重启
4. `BASE_URL=https://<域名> bash scripts/verify.sh`
5. 更新 service 注册信息里的地址为域名版

## 备选路径：aliyun（121.43.80.231）的约束（仅当 60.205 彻底不可用时）

SSH 免密已通，但必须清楚三件事：

1. **内存 1.6GB、仅剩 131MB** —— SceneGuide node 进程约 80–100MB，能塞但挤；
   必须加 systemd `MemoryMax=200M` 防止挤垮在营项目
2. **80 端口是共享 nginx**（商大元境 /campus、小票机 /cjy 都在）——
   只能以路径前缀 `/sg/` 接入（`location /sg/ { proxy_pass http://127.0.0.1:3100/; }`），
   这要求前端全部资源引用与 fetch 改为**相对路径**（改动约 10 处），
   且 `demo/pay` 的内部回环 fetch 需改为 `http://127.0.0.1:3100` 直连
3. 改 nginx 是在**在营项目**的共享配置上动刀 —— 动手前先 `cp nginx.conf nginx.conf.bak.$(date +%s)`

> 结论：除非 60.205 彻底不可用，否则不要走这条。若要走，我（Agent）可以完成相对路径改造，你说一声。

## 风险与回退

| 风险 | 处置 |
|---|---|
| 3100 被运营商/安全组拦截 | 换 8443/9090 再试；或等域名备案后走 80/443 |
| 服务信息审核驳回 IP 地址 | 备案域名通过后用域名重提（材料不变，只换地址） |
| 与 DrCopilot 抢资源 | SceneGuide 空闲 ~80MB；可加 systemd `MemoryMax=256M` |
